## Unreleased

- Freeze a thread's tool list for prefix-cached providers (MultiDex/Lite and DeepInfra) for the life of its context window. Tools that an MCP server or the Apps catalog publishes mid-thread are no longer inserted into a long conversation, since any change ahead of the conversation makes the server recompute all of it; they join with the next context window or thread. While the conversation is still under ~16K estimated tokens (a server finishing startup), new tools are still added. A requested change (MCP reconnect or `mcpServer/refresh`, MCP or plugin OAuth login, plugin install/uninstall, skill MCP dependency install) renews the list once, with an info log. OpenAI and other providers are unchanged.
- Make `inherits_tools_on_continuation` a tri-state (`"auto"` default, `true`, `false`). `auto` omits unchanged tools on `previous_response_id` continuations only when the continued response advertised `responses.tools-inheritance/1` in `X-Inference-Ultra-Capabilities`, and stops for an endpoint whose `response.completed` does not echo the omitted tools. OpenAI and other providers are unchanged.
- Compress Responses request bodies with zstd for the Lite-backed MultiDex providers by default, negotiating per endpoint and resending uncompressed once when a server cannot decode them; OpenAI and remote providers are unchanged. Add the `request_compression` (`auto`/`zstd`/`none`) and opt-in `inherits_tools_on_continuation` provider options, the latter omitting unchanged tools on `previous_response_id` continuations.
- Fix missing command lifecycle events when unified exec cannot create a process, preserving approval rejection and sandbox retry behavior. Thanks @Marvinthebored ([#44557](https://github.com/openai/codex/issues/44557)).
